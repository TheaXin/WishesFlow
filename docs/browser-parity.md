## 实施约束

- 不修改或清空既有 wishflow.browser.v1 记录。新结构升级应保留原始备份，明确归属资料，迁移失败不能覆盖旧数据。
- 昵称属于本机资料区分，不作身份认证或隐私保护承诺。
- 保持 product-site 产品介绍与 app 实际应用的边界；介绍页不得宣称尚未实现的功能。
- 使用共同业务样例核对 Python SQLite 与 JavaScript 的结果，避免只写各自都能通过的孤立测试。
- 不凭测试数量认定完整；需要逐页实际操作、刷新/资料切换、历史日期、空状态、重复操作、存储失败、导入失败及升级迁移验证。
- 布局检验：桌面侧栏与390px手机导航，键盘可用、无横向溢出；逐页截图检查。
- 测试通过后发布同仓库 main，等待 GitHub 测试与部署成功，核对线上 build.json 与源码 commit。

## 保留的实现差异

SQLite 与 localStorage 存储方式不同，均没有认证或跨设备同步。浏览器版多了备份页、心愿状态筛选、趋势数据表和近期记录；Streamlit 版使用自己的图表与控件。浏览器版金额按分，最多支持一亿元且两位小数；本地数据库为浮点金额。旧数据无解锁时间时不伪造时间，后续新解锁会记录时间。v2 不新增本地版也没有的删除/改价功能。
